# KOGG functionality audit — 20 November 2026

## Outcome

The local presentation core is healthy under the automated suite and sampled browser workflows. This is not a claim that every browser, physical projector, microphone, phone, OBS installation or live cloud service has passed.

Baseline: main at b531d10, browser source v136. Audit fixes target v137. Production remains v135; the published Windows preview contains v127 and the web ZIP is v125. Full open Ibibio is already in the repository's Base bundle, but is not yet on production. Do not confuse GitHub pushes with deployments.

## Confirmed defects repaired

| Finding | Effect before repair | Repair and evidence |
| --- | --- | --- |
| Connected Bible verse numbering | Missing/omitted verses could shift later text under the wrong reference. | Preserve empty verse positions in NLT and API.Bible results; regression covers gaps and later NLT windows. |
| API.Bible response parsing | Parser expected a flat adapter format rather than the documented data/content/tag/items envelope. | Parse the documented nested response, exclude headings/notes, preserve inline punctuation and paragraph spacing. Fixture test uses the official response structure; no production credential available to certify licensed access. |
| NLT partial chapter cache | A later-window 503/rate failure could silently save an incomplete chapter. | Fail the request without populating the chapter cache; retry remains available. |
| Late Strong's lookup | A slow lexicon load could overlay a word card on content projected after the lookup began. | Check output identity and latest lookup token after loading; the latest word click wins. |
| Late Bible selection/download | A slow version selection could re-project the old reference over a newer announcement or song. | Keep the current output if it changed during loading, including optional Bible selection. A delayed-selection regression proves this. |
| Reduced-motion prompt overlap | A fixed prompt inside the filtered header used the header as its containing block and covered navigation. | Move the prompt to the body; verify its rectangle clears the desktop header (79 px header bottom versus 660 px prompt top). |
| Landing/provider copy | Two rendered Base descriptions and a promise card still said three Bibles; licensed-version copy implied universal access. | Consistent four-Bible copy, correct API.Bible link, edition-specific access wording and NLT retirement notice. |

No new runtime dependency, audio payload, mandatory Bible pack or animation framework was added. Existing session caching, shared in-flight provider requests, on-demand optional packs and offscreen animation suspension remain intact. v137 refreshes the cache manifest; canonical LF files and all 93 hashes are verified.

## Open issues, ordered by impact

1. **P1 — KOGG cloud endpoint unavailable.** Browser Connect phone returned “Online remote unavailable.” curl could not resolve `ibzbtthorsjtkvlmzsps.supabase.co`; an explicit query to resolver 1.1.1.1 also returned DNS name does not exist, while jsDelivr was reachable. The signed-in Supabase dashboard redirected the KOGG project URL to Organizations and only exposed NalahDelta's different project. This establishes an unavailable configured endpoint, not whether the KOGG project was paused, deleted or moved. Restore access to the original KOGG project and verify status/URL; do not substitute the unrelated project or create an empty replacement. Then run a real guest-phone Next/Blank/Resume test and private media sync between two devices.
2. **P1 — Production deploy blocked by Cloudflare access.** Current OAuth account cannot access the recorded owner of kogg-presenter. Live asset hashes still differ from v136 and the Ibibio JSON path returns HTML fallback. Reconnect the account owning the existing Pages project, deploy v137 and compare canonical production hashes. Keep the existing site and data.
3. **P1 — NLT public API ends 1 January 2027.** Tyndale explicitly announces the endpoint closure and key expiry. Current source now warns users. Obtain an approved replacement connection and migrate before retirement; no replacement licence is claimed. Base open Bibles remain independent.
4. **P1 — Managed API.Bible integration is unfinished.** The parser repair does not complete server-side credential handling, FUMS usage reporting, per-device cache refresh rules or licensed schedule persistence. Provider replies permit a managed connection and offline reporting queue under their terms. Build the proxy and reporting queue before advertising broad managed licensed access; store references and attribution as required instead of assuming every text can be bundled/synced. A user's supplied key and edition eligibility are separate from redistribution permission.
5. **P2 — Releases have diverged.** Browser source, live site, Windows installer and downloadable web ZIP differ. After cloud access is restored, build a release from one pinned commit, test the clean archive/installer and label the actual build in Tools. CI should validate hashes, test the published site and prevent landing download claims from drifting.
6. **P2 — Real-device acceptance remains.** Run one short church-service rehearsal on a low-memory Windows laptop, Android phone, iPhone/iPad, actual extended display and OBS. Include offline relaunch, network loss/recovery, one image/video schedule, microphone permissions, font fitting and paired remote revocation. Preserve this as a release checklist.
